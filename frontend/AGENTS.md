# frontend — Agent Guide

pnpm workspace with the Admin SPA and the embeddable widget. Read the root `AGENTS.md` first; this file adds
frontend rules. Design: `docs/llm-steward-design.md` §9 (Admin pages, roles, widget) and §5 (confirmation card).

## Layout (create in P6)

```
frontend/
  package.json                # pnpm workspace
  apps/admin/
    src/client/               # GENERATED by @hey-api/openapi-ts — never edit by hand
    src/routes/               # dashboard, memories, users, kb, review, playground, activity, jobs, providers, settings
    src/components/           # shadcn/ui + DetailDrawer, DiffView, StatusBadge, SyncBadge
    tests/                    # Playwright
  packages/widget/            # @llm-steward/widget: <SuggestionCard />, <MemoryPanel />
```

In production the Admin build is served by FastAPI; there is no separate frontend server.

## Rules

1. **The OpenAPI spec is the only contract.** Call the API only through the generated client (`src/api/live.ts`
   adapts it to the view types; `src/api/endpoints.ts` picks live or mock). If an endpoint you
   need is missing, add it to the backend first (or record it as a blocker) — never mock it in production code.
2. **No governance logic in the browser.** Status transitions, risk levels, scores and permissions come from the
   API. The UI shows them and sends user decisions; it never decides whether something is `verified`.
3. **Two auth contexts.** The Admin has no login, accounts or roles (decided 2026-11-10): in live mode
   (`VITE_API_MODE=live`) it connects with the backend's static `STEWARD_ADMIN_TOKEN`, kept in sessionStorage for
   the tab only; mock mode (the demo) needs nothing. The backend is the only enforcement. The widget uses a
   short-lived **user token** minted by the host app's backend (`POST /v1/tokens/user`) — never an API key in the
   browser.
4. **Every list** supports filter, search and cursor pagination; clicking an object opens the right-hand detail
   drawer with content, metadata, provenance links and change history.
5. **No native `alert` / `confirm` / `prompt`.** Use the shadcn dialog components. Destructive actions (delete user
   memories, deprecate, revoke key) need an explicit confirm dialog; rejecting a candidate requires a reason.
6. **Widget is embeddable.** `packages/widget` must not depend on `apps/admin`, must not assume the Admin's router,
   theme or global CSS, and keeps its bundle small.
7. API keys are shown once on creation and never again.

## Testing

- Unit/component tests for non-trivial UI logic.
- Playwright covers the two P6 acceptance flows: review a high-risk candidate and see it sync to WeKnora; find a
  gap in the Retrieval Playground and add it to the KB.
- Tests run against a backend on the `native` profile with fake LLM — never a real model.

## Commands

```
pnpm install
pnpm generate-client              # regenerate src/client from the backend OpenAPI spec
pnpm typecheck && pnpm lint && pnpm test
pnpm e2e                          # Playwright
```
